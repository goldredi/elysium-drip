═══ ЧТО ЭТО ═══

Emojirean — система шифрования текста в эмоджи. Каждый «язык» (токен) определяет
уникальный алфавит: какие эмоджи соответствуют каким буквам. Без токена — расшифровка
невозможна. Визуально шифр выглядит как арт из эмоджи.


═══ КАК РАБОТАЕТ КОДИРОВКА ═══

1. АЛФАВИТ
   - 300+ эмоджи в пуле (животные, растения, символы, космос, и т.д.)
   - При создании токена каждой букве назначаются случайные эмоджи
   - Омофоны: гласные получают 3-8 вариантов, согласные 2-3
   - Это значит что одно и то же слово каждый раз выглядит по-разному

2. БИГРАММЫ
   - 120 частых пар букв (НА, СТ, ЧТ, ПР, ОТ...) кодируются одним эмоджи
   - Сжимает текст на ~20-25%
   - Декодер автоматически знает что это биграмма

3. СЖАТИЕ (deflate)
   - Для длинных/повторяющихся текстов используется deflate-компрессия
   - Текст → UTF-8 → deflate → каждый байт → эмоджи через byteMap (256 уникальных)
   - Маркер 0xC0 в начале отличает сжатые данные от буквенного кодирования
   - Автоматический выбор: сжатие vs буквы — выбирается меньший результат

4. ФОРМАТ ТОКЕНА
   - Base64-строка содержащая JSON с маппингами
   - Компактный формат: буквы и эмоджи хранятся как индексы пула
   - master token = полный (encode + decode + alphabet)
   - reader token = только decode (алфавит скрыт)


═══ ФОРМАТЫ ВЫВОДА ═══

FLAT    — эмоджи подряд без пробелов, одна строка
GRID    — квадратная сетка с декоративным padding
DIAMOND — ромбовидная форма
TRI     — треугольник (расширяющийся)
CROSS   — крестообразная форма
FRAME   — пустая рамка
ART     — пиксельные фигуры (zodiac, nebula, eye, scatter, pyramid, dna, heart, skull,
          orbit, wave, glyph, stars) — случайная фигура каждый раз

Все форматы декодируются одинаково — декодер игнорирует:
  - ASCII deco символы (☠ ∴ ᚠ ⠿ и т.д.)
  - Пробелы и переносы строк
  - Frame-эмоджи (⬛ 🔲 и т.д.)


═══ СТИЛИ ДЕКОРАЦИИ ═══

5 стилей ASCII для рамок и разделителей:
  WING   — ✮☠☂☁☀☼☽☾
  BOX    — ░▒▓│┤╔╗╚╝
  MATH   — ∴∵∞≡∇⋮∑∏
  RUNE   — ᚠᚢᚦᚨᚱᚲᚷᚹ
  BRAILLE — ⠿⠯⠷⠾⠸⠼⠻⠽

Стиль привязан к токену и выбирается случайно при создании.


═══ ДОПОЛНИТЕЛЬНЫЕ МЕХАНИЗМЫ ═══

STEALTH MODE — шифр-эмоджи прячутся среди обычных (😊❤️🔥). Каждый 4-й — настоящий.
              Декодер определяет stealth по якорю 🫥

FINGERPRINT — 5 эмоджи = SHA-256 хэш токена. Совпадает у master и reader одного языка.
              Визуальная проверка подлинности.

NULL NOISE — случайные эмоджи из null-пула вставляются между кодом.
            Декодер знает null-эмоджи токена и фильтрует их.

TTL — время жизни: количество сообщений или дата. После исчерпания токен удаляется.


═══ СИСТЕМА ДОСТУПА ═══

- Генерация токенов заблокирована для всех по умолчанию
- Для разблокировки нужен одноразовый ключ доступа
- Ключи генерируются через admin panel или через бот (/genkey)
- Отслеживание: кто, когда, с какого IP активировал ключ
- Импорт токена (reader) доступен всем без ключа


═══ TELEGRAM BOT ═══

Команды:
  /start          — приветствие + ссылка на webapp
  /help           — список всех команд с описаниями
  /token <base64> — загрузить токен (без webapp)
  /encode <text>  — закодировать сообщение
  /decode         — ответить на сообщение чтобы раскодировать
  /key <key>      — активировать ключ доступа (один на человека)
  /genkey [N] [note] — (admin) сгенерить N ключей
  /stats          — (admin) статистика ключей и пользователей

Inline режим:
  @bot_username <текст> → 3 варианта: ARTISTIC, FLAT, DIAMOND
  Выбираешь и отправляешь в любой чат

Автодекод:
  Пересылаешь боту сообщение с эмоджи → бот пытается декодировать
  (нужен загруженный токен)

Ограничения:
  - Один ключ доступа на одного человека
  - Если уже активировал — повторно не получится
  - Неправильный ключ → ошибка "ключ не найден"
  - Использованный ключ → ошибка "ключ уже использован"


═══ АРХИТЕКТУРА ═══

emojirean.html  — standalone webapp (один файл, всё работает offline)
admin.html      — панель управления (ключи, статистика, токены)

backend/        — FastAPI сервер
  main.py       — REST API (auth, languages, keys, admin)
  models.py     — SQLAlchemy модели (User, Session, Language, EncodeLog, AccessKey)
  auth.py       — JWT + PBKDF2 аутентификация
  config.py     — env конфигурация
  database.py   — PostgreSQL async engine
  redis_client.py — Redis подключение

bot/            — Telegram bot
  main.py       — команды, inline, автодекод
  engine.py     — Python-порт движка кодирования

docker-compose.yml — PostgreSQL + Redis + Backend + Bot


═══ ЗАПУСК ═══

1. Создай бота через @BotFather → получи BOT_TOKEN
2. Включи inline mode в @BotFather: /mybots → бот → Bot Settings → Inline Mode → Turn on
3. Заполни .env:
   BOT_TOKEN=<твой токен>
   ADMIN_SECRET=<секрет для админа>
   ADMIN_TELEGRAM_IDS=<твой telegram ID>
   SECRET_KEY=<любая длинная строка>
4. docker compose up --build -d
5. Открой http://localhost:8000 — webapp
6. Открой admin.html в браузере — генерация ключей
7. Напиши боту /start

Для standalone (без сервера):
  Просто открой emojirean.html в браузере.
  Всё работает локально через localStorage.


═══ ПОЛУЧЕНИЕ TELEGRAM ID ═══

Напиши @userinfobot в Telegram — он покажет твой ID.
Этот ID нужно прописать в ADMIN_TELEGRAM_IDS в .env


═══ КАК ГЕНЕРИТЬ И РАЗДАВАТЬ КЛЮЧИ ═══

Способ 1: Через бот (рекомендуется)
  1. Пропиши свой Telegram ID в ADMIN_TELEGRAM_IDS в .env
  2. Запусти бота
  3. Напиши боту: /genkey 5 для друзей
     → Бот выдаст 5 одноразовых ключей с пометкой "для друзей"
  4. Скопируй ключ и отправь человеку
  5. Человек пишет боту: /key <ключ> → ключ активируется
  6. Затем открывает веб-приложение и вводит этот же ключ → генерация разблокирована
  7. Проверяй кто активировал: /stats

Способ 2: Через admin panel
  1. Открой admin.html в браузере
  2. В секции ACCESS KEYS нажми generate
  3. Скопируй ключ
  4. Отправь человеку
  5. Человек вводит ключ в emojirean.html в поле "введи ключ доступа"

Правила:
  - Один ключ = одна активация
  - Один человек = один ключ (бот не даст второй)
  - В /stats видно: кто, когда, с какого IP
  - Ключи можно удалять из admin panel


═══ БЕЗОПАСНОСТЬ ═══

- Без токена расшифровка невозможна (300^33+ комбинаций)
- Омофоны: каждое сообщение выглядит иначе
- byteMap: 256! перестановок для byte-level кодирования
- Сжатие скрывает длину исходного текста
- Reader token: даёт только decode, алфавит скрыт
- TTL: самоуничтожающиеся токены
